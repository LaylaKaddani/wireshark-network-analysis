# Wireshark Network Analysis

## Overview

This repository presents a practical analysis of network traffic using **Wireshark**. The project explores how common network protocols operate by capturing and inspecting packets exchanged during local and remote communications.

The analysis focuses on three fundamental protocols:

* Address Resolution Protocol (ARP)
* Internet Control Message Protocol (ICMP)
* Domain Name System (DNS)

---

## Objectives

This project aims to:

* Capture and inspect network traffic using Wireshark.
* Understand how devices communicate on a local network.
* Analyze ICMP traffic generated by network connectivity tests.
* Observe DNS name resolution before remote communications.
* Develop practical packet analysis skills used in networking and cybersecurity.

---

## Environment

* Operating System: Windows
* Network Interface: Wi-Fi
* Packet Analyzer: Wireshark
* Command Line Tools:

  * `ipconfig /all`
  * `ping`
  * `arp -a`

---

# ARP Analysis

The Address Resolution Protocol (ARP) enables devices on the same local network to associate an IPv4 address with its corresponding MAC address.

The network configuration was first identified using the `ipconfig /all` command.

![Network Configuration](screenshots/ipconfig-all.png)

After starting the packet capture, the `arp` display filter was applied to isolate ARP traffic.

![ARP Filter](screenshots/arp-filter.png)

To generate ARP packets, a `ping` request was sent to another device on the local network.

![Ping Command](screenshots/ping-gateway.png)

The capture shows an **ARP Request**, where the sender broadcasts a request to discover the MAC address associated with an IPv4 address.

![ARP Request](screenshots/arp-request.png)

The destination host answers with an **ARP Reply**, providing its MAC address.

![ARP Reply](screenshots/arp-reply.png)

Finally, the ARP cache was inspected using the `arp -a` command to verify the IP-to-MAC mappings stored by the operating system.

![ARP Cache](screenshots/arp-cache.png)

---

# ICMP Analysis

ICMP packets were analyzed by sending `ping` requests.

A first capture was performed between devices located on the same local network. The traffic shows the exchange of **Echo Request** and **Echo Reply** packets.

![Local ICMP Communication](screenshots/icmp-local.png)

A second capture targeted remote hosts. Unlike local communication, packets are forwarded through the default gateway before reaching their destination.

![Remote ICMP Communication](screenshots/icmp-remote-google.png)

This comparison illustrates the difference between communications within the same network and communications routed over external networks.

---

# DNS Analysis

When a remote host is contacted using its domain name, the operating system first performs a DNS lookup to obtain the corresponding IPv4 address.

The Wireshark capture shows the DNS query and the server response before the ICMP packets are transmitted.

![DNS Resolution](screenshots/dns-resolution.png)

# Protocol Summary

| Protocol | Role                                                         |
| -------- | ------------------------------------------------------------ |
| ARP      | Maps IPv4 addresses to MAC addresses on the local network.   |
| ICMP     | Verifies connectivity between network devices.               |
| DNS      | Resolves domain names into IPv4 addresses.                   |
| IPv4     | Provides logical addressing for communication between hosts. |
